07 — Introduzione a LiteLLM e alle feature del rilascio stable

Questo documento presenta LiteLLM e le feature disponibili nel rilascio stable usato in questo repository: 1.108.2, linea LTS 1.108. L'installazione è nel documento 01. La configurazione con GitHub Copilot è in 02 §4. La sicurezza è in 03.

1. Che cos'è LiteLLM

LiteLLM è una libreria open source che offre una sola interfaccia, nel formato OpenAI, per chiamare più di 100 modelli LLM (S-182). Si usa in due modi:

Modo Che cos'è Per chi
Python SDK Libreria per chiamare i modelli dal codice: completion(), embedding(), router con nuovi tentativi e fallback Sviluppatori che scrivono un'applicazione
Proxy Server (LLM Gateway, AI Gateway) Servizio da ospitare in proprio, compatibile con l'API OpenAI Team di piattaforma che controllano l'accesso ai modelli in un'organizzazione

Questo repository usa il proxy: i client compatibili OpenAI lo usano senza modifiche al codice. VS Code lo vede come un Custom Endpoint (06 §4).

2. LiteLLM tra VS Code e i provider

  • VS Code manda il nome di un alias (model_name). Il proxy lo traduce nel modello del provider e nel suo formato (S-022).
  • Le chiavi dei provider stanno solo sul gateway. Il client ha una chiave del gateway.
  • Il proxy espone i tre formati che VS Code usa: Chat Completions, Responses e Messages (S-028, S-029).

Tag delle immagini Docker

Tag Comportamento Uso in questo repository
1.108.2 (o v1.108.2) Versione fissa Sì (D-018)

Raccomandazione del vendor per la produzione: fissa l'ultima versione stable 1.x.x (S-185). I tag mobili sono stati compromessi nell'incidente di ottobre 2026 (S-104).

La versione 1.108.2. È una patch sopra la 1.108.1, senza nuove migrazioni del database e senza nuovi provider. Contiene correzioni, tra cui: livelli di servizio di Bedrock Converse, PDF in base64 verso Claude, instradamento con tag e con prompt cache, righe di spesa durante il riavvio di PostgreSQL, response_format: json_object sulle rotte openai/responses/* (S-119).

⚠️ Dopo la prova LTS la politica di supporto può cambiare: la pagina non dice cosa succede alla fine del mese. Controlla S-184 prima del talk.

5. Feature Enterprise

Alcune feature richiedono una licenza Enterprise (S-183).

Area Feature Enterprise
Accesso SSO per l'Admin UI; autenticazione JWT
Sicurezza Integrazione con secret manager (AWS, Google, Azure, HashiCorp Vault); liste di indirizzi IP permessi; rotazione delle chiavi; limiti di dimensione delle richieste; controllo delle rotte pubbliche e private
Audit Log di audit con periodo di conservazione
Log e privacy Log per team; disattivazione dei log per un team
Aspetto Pagina Swagger personalizzata

⚠️ Per altre voci (metriche Prometheus, controllo dei guardrail per chiave, esportazione della spesa) la pagina non dice in modo chiaro se serve la licenza. Controlla la pagina prima di progettare su queste feature.

Conseguenza per questo repository: la baseline raccomanda l'SSO per l'Admin UI (02 §4.1), ma l'SSO è una feature Enterprise. Senza licenza proteggi l'Admin UI con il bind su 127.0.0.1 e la procedura del primo amministratore (S-148).

Gli esempi non usano: guardrail, cache, bilanciamento tra deployment, MCP Gateway, Agent Gateway, integrazioni di osservabilità.

7. Rischi

Un gateway concentra le chiavi di tutti i provider: una compromissione ha un impatto più grande di una chiave su un client. Nel 2026 LiteLLM ha avuto due incidenti di supply chain e vulnerabilità critiche del proxy (S-104, S-105, S-106).

Applica sempre l'hardening minimo di 02 §4.1 e le pratiche di 03: versione fissa, bind su 127.0.0.1, solo virtual keys agli sviluppatori.

8. Quando usare LiteLLM

Contesto Scelta
Un solo sviluppatore, pochi provider BYOK nativo (06)
Team con chiavi condivise, budget, elenco dei modelli permessi, log centrali Gateway LiteLLM con hardening
Organizzazione con Copilot Business o Enterprise Valuta prima il BYOK enterprise di GitHub (06 §2)

Il criterio completo è nella decisione D-017.
